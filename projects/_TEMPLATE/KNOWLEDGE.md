# Project Durable Knowledge

Status: active
Purpose: preserve compact, stable facts, definitions, identifiers, corrections, or reference context that materially matter to this project and do not belong in project current state or decisions.

This is not a project transcript or document archive.

## What belongs here

Examples:

- stable project-specific facts;
- standing project definitions or terminology;
- identifiers or constraints repeatedly needed across sessions;
- factual corrections that should stop stale project assumptions from resurfacing.

Prefer another registered canonical project source when one already exists. Do not duplicate whole source documents here.

## Entry format

### K-001 — Example only

- **Status:** active | superseded | stale
- **Knowledge:** one concise project-local durable fact, definition, identifier, or correction.
- **Basis / source:** user explicit | repository source | external source | other stated basis
- **Last verified:** YYYY-MM-DD or not established
- **Review after:** YYYY-MM-DD, event/condition, or not needed
- **Stale when:** event/date/condition, or none known
- **Supersedes:** none or prior K ID
- **Superseded by:** none or later K ID

## Rules

- Project-local knowledge stays here rather than root `KNOWLEDGE.md`.
- Current objectives/work/constraints/open questions belong in project `CURRENT.md`.
- Governing choices belong in project `DECISIONS.md`.
- Stable collaboration preferences generally belong in root `WORKING_STYLE.md` unless the project front door explicitly scopes a project-specific convention.
- Prefer an existing canonical source over duplication.
- If support is ambiguous or model-inferred, ask before activating durable knowledge.
- Use freshness metadata when time can change the fact.
- A passed `Review after` trigger means scrutinize/reverify when relevant; it does not automatically make the entry false.
- Supersede corrections rather than keeping contradictory active entries.

Soft budgets are declared in root `PROTOCOL.yaml`. Crossing a project knowledge budget is a `Watch` signal requiring review, not an instruction to delete valid knowledge.
